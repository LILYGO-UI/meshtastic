# LILYGO UI Meshtastic 开发规范

本文是本应用的 UI 开发规范。新增或修改页面、组件、布局、样式、文案或字体时
必须遵守；开始编辑前先检查现有页面、公共组件和测试。

## 架构和数据流

- Model/domain 保存业务状态和领域规则，必须能在不初始化 LVGL 时测试。
- ViewModel 将领域状态转换为展示状态，通过 Subject 发布变化并提供用户命令。
- View 只创建和布局 LVGL 对象、绑定状态并转发事件，不得直接修改 domain。
- 页面代码位于 `src/pages/<page>/`；应用生命周期和全局导航位于 `src/app.cpp`
  与 `src/app_router.*`。
- 页面切换必须延迟到当前 LVGL observer 或事件回调结束后，禁止同步删除触发
  回调的对象。

依赖方向固定为 `View -> ViewModel -> Model/domain`，状态变化不得依赖周期性重建
整页来刷新。

## 语义颜色

公共颜色必须在 `src/components/components.hpp` 中定义语义角色。页面不得重复
硬编码同一用途的色值，也不得用渐变替代明确的颜色角色。

| 角色 | 用途 | 色值 | 透明度 |
| --- | --- | --- | --- |
| 页面背景 | 页面根容器 | `#F2F2F7` | `100%` |
| 容器背景 | 面板和卡片 | `#FFFFFF` | `100%` |
| 容器标题 | 标题和小标题 | `#1A1A1A` | `100%` |
| 正文 | 正文和主要数值 | `#000000` | `100%` |
| 边框 | 分隔线和容器边界 | `#D8DDE3` | `100%` |
| 主操作 | 主要按钮背景 | `#20262D` | `100%` |

蓝色用于导航选中和信息强调，绿色用于成功/在线状态，红色用于错误状态，橙色用于
次要频道，浅色填充用于头像和搜索区域。这些扩展角色仍必须集中定义并保持完全不透明。

## 字体和文本

- 显示文本的 UI 源文件必须包含 `<cm0/typography.h>`。
- 在 `lv_init()` 后调用 `lilygo_ui_font_get()`，只使用 `14`、`22`、`28`、`36`
  和 `48`。设置样式前必须检查返回指针非空。
- 同一信息层级使用一致字号，不得按视口连续缩放字体。
- 公共 UI 不得引用 `lv_font_montserrat_*`，不得修改、释放或重新打包 AppKit
  提供的 Inter、Source Han Sans CN 和 Font Awesome 字体。
- 中西文混排使用同一 AppKit composite font，不拆分标签或依赖系统 fallback。
- 动态文本必须有明确的换行或截断策略；先调整文案和布局，不以缩小字号修复溢出。

只有 AppKit 确实缺少所需字形时，才允许在 `assets/fonts/` 放置有来源和许可证的
应用专用字体。它必须按当前字号运行时加载，以同字号 AppKit 字体为 fallback，并在
所有引用对象删除后释放。

## 响应式布局

- 页面主体必须使用 LVGL Flex 或 Grid，结合百分比、`LV_SIZE_CONTENT`、最小尺寸、
  间距和滚动容器分配空间。
- 固定像素仅用于图标、边框、间距、命中区下限和其他明确 token，不得用大量绝对
  坐标组织页面或复制横竖屏页面。
- 断点依据父容器实际可用宽高，不依据 CPU、设备型号或展示模式。
- 运行时尺寸更新必须可重复执行，并保留业务状态、焦点、滚动位置和输入。
- 长文案、fallback 字体和内容增长时，容器必须扩展、换行、重排或滚动；主要操作
  始终可见、可达并有足够命中区域。

## 对象和生命周期

- View 在调用者传入的 `parent` 下创建顶层对象，不假设 parent 是 screen/display。
- 页面 View 保存自己的顶层对象并提供可重复销毁流程；父对象删除子对象后清空所有
  缓存指针，禁止重复删除。
- `user_data` 指向对象的生命周期必须覆盖事件注册期。
- 对象绑定 observer 随对象销毁；全局 observer、timer 和输入监听器必须显式注销。
- ViewModel 必须比绑定其 Subject 的 View 存活更久；Subject 不可复制或移动。
- 关键测试对象必须设置稳定、语义化的 `lv_obj_set_name_static()` 名称。

## 页面和公共组件

完整页面通常包括页面 ViewModel、View、应用装配、用户行为测试和更新后的预览。
公共组件只有在至少两个页面复用，或承担公共样式、绑定、所有权时才放入
`src/components/`。组件必须以调用方 parent 的可用尺寸布局，并声明 callback、
observer、timer 和销毁责任。

## UI 验收

UI 修改至少必须完成主机构建和测试，并人工检查 `320x568`、`568x1232`、
`1232x568`、`1024x768` 渲染。测试和检查需要覆盖：

- 所有主页面与 detail 页面，而不只是默认空态；
- 运行时横竖屏切换以及状态、焦点、滚动和输入保持；
- 长节点名、长 endpoint、长消息和中西文混排；
- 文本缺字、错误 fallback、重叠、裁切和不可达操作；
- 页面销毁后的 observer、timer、回调和指针生命周期。
